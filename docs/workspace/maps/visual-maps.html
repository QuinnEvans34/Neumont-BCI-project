Runtime and ownership / 3

One producer, multiple viewers

Open SVG   /   Editable source   /   PDF page 4
Each viewer polls snapshots at its own nominal 4 Hz cadence. A viewer never reads the board. Sequence numbers belong to the producer; the browser ignores repeated or out-of-order frames. An open WebSocket does not mean the headset is connected or the input is usable.
EEG to game input / 4

Acquisition and fan-out

Open SVG   /   Editable source   /   PDF page 5
Cyton's configured layout is eight EEG channels at 250 Hz. SDK reads arrive in batches; their sizes are not assumed to equal a feature window. Full-rate recording and experiment analysis branch before the game amplitude gate. Chart telemetry is a reduced view of the rolling buffer, not the samples used for decoding or recording.
EEG to game input / 5

Per-window processing and calibration

Open SVG   /   Editable source   /   PDF page 6
Baseline collection and the rolling play feature share analyze(); the diagram separates their consumers. Baseline time means accepted data: rejected windows do not advance the 60-second target. Live EEG requires an explicit scoring-channel selection before calibration. Raw mains-hum RMS is measured separately for diagnostics; the notch filter does not establish electrode contact.
EEG to game input / 6

Browser acceptance

Open SVG   /   Editable source   /   PDF page 7
isUsable() checks both the monotonic receipt age and the producer's wall-clock timestamp against a two-second limit; it also rejects a producer timestamp over two seconds in the future. Acquisition freshness is checked separately by the backend. Recovery of usable input does not press Resume for the player.
Recording, joins and review / 7

Research / Dev Mode capture

Open SVG   /   Editable source   /   PDF page 8
The selected format creates CSV, SQLite, or both. The default destination is data/research/; BCI_RESEARCH_DIR and configured destinations can change it. Recording may begin before connection or partway through a session and can span reconnects, recalibration and game switches. Beginning mid-session is marked as partial rather than inventing earlier data.
Recording, joins and review / 8

Trace one event back to EEG

Open SVG   /   Editable source   /   PDF page 9
These are logical joins in the recorded schema, not a claim that every storage format enforces foreign keys. The input-frame reference identifies the score the game consumed. Clock-aligned sample estimates identify nearby raw data with uncertainty; browser event times are not exact hardware sample triggers. Score-only synthetic frames have no raw EEG window.
Recording, joins and review / 9

Save, recover and inspect

Open SVG   /   Editable source   /   PDF page 10
Stop does not stop acquisition or automatically end ordinary gameplay. A recording finalizes asynchronously; file completion and losses determine its final state. Owner loss after five seconds or a full storage queue ends capture with an explicit incomplete/failed outcome. Export reads persisted files; SQLite-only research recordings can still export CSV ZIPs. Inspect active capture in Live rather than treating it as a finalized recording.

From a network frame to a rendered game

React owns navigation and controls. Mutable refs hold the latest controls/model for animation callbacks. A missing telemetry update is treated as an outage; an observed new session or transition into calibration invalidates rounds tied to the old comparison reference.
Frontend components and function paths / 12

Game update loops

Open SVG   /   Editable source   /   PDF page 13
Paused game progress does not catch up after a background-tab delay. Presentation can still finish a fall animation or settle an ambient visual; those animations do not imply gameplay time is advancing. Research state snapshots for Cairn/Garden target 20 Hz rather than copying every display frame. Balance Beam consumes the shared score but has no equivalent dedicated game-state trace class in this implementation.

Startup and acquisition tick

Open SVG   /   Editable source   /   PDF page 14

The HTTP control routes also use the service lock when changing acquisition or baseline settings. stream() sends snapshots independently of the worker, as shown in the runtime map.

Player journey and game lifecycle / 16

Per-game lifecycle

Open SVG   /   Editable source   /   PDF page 17
This is a conceptual lifecycle across the games, not a single enum in the code. A new acquisition or recalibration resets every state to NotStarted; that shared reset path is shown in the interruption map below. Full bloom is a Garden milestone rather than a fall/loss; growth caps at one. A new Garden plant may include the optional settle-in. Cairn and Balance rounds end on falls; a new round resets game state while retaining a valid current session baseline.

Experiment presentation and analysis / 18

Shared start and ownership

Open SVG   /   Editable source   /   PDF page 19
Start requires raw input from live, replay or simulated_eeg, not score-only synthetic. Alpha calibration is not required. The UI and backend reject overlap with an active research recording or another experiment. SSVEP pages additionally require a passing display check and acknowledgement; Cards also validates its posterior-channel configuration.
Experiment presentation and analysis / 19

Three different protocols

Open SVG   /   Editable source   /   PDF page 20
Cards supports diagnostic evaluation that abstains when usable thresholds are unavailable; freezing does not guarantee acceptance. Circle is an observation/recording experiment, not a gaze classifier. Bilateral records the chosen follow/fixate instruction condition and descriptive metrics; it is not a P300 classifier or therapeutic assessment.
Experiment presentation and analysis / 20

Where decoding happens

Open SVG   /   Editable source   /   PDF page 21
In Cards, the instructed target is used for setup/evaluation labels. The decoder computes correlations from raw EEG and frequency references; it does not read the cue as its answer. Replayed resting EEG and generated signals can exercise this software path without validating a new participant response.
Development, build and release / 21

Install, run and build

Open SVG   /   Editable source   /   PDF page 22
There is one root npm package. The frontend's HTML/source live under apps/web; there is no separate frontend package install. The Python runtime and optional asset-generation tools have separate dependencies. Building the frontend does not launch Python or deploy the app.

Recording conversion and no-headset game testing

Open SVG   /   Editable source   /   PDF page 25
The converter maps supported GUI text rows to BrainFlow's 24-row Cyton format. score_trace reuses the backend's feature/calibration pipeline with a deterministic virtual clock; it is not a substitute for testing the real board or fresh stimulus responses. Cairn photo assets

Open SVG   /   Editable source   /   PDF page 26
The asset script is an on-demand authoring tool, not part of npm run build. Segmentation uses optional heavyweight model tooling; recomposition uses cached masks and image-processing libraries. Its defaults keep original photos under ignored images/dump and write reusable generated assets to the frontend asset directory.
